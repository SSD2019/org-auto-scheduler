* Org Auto Scheduler

Org Auto Scheduler is an Emacs plugin that automatically schedules tasks in your Org mode files based on various factors such as priority, deadline, effort, and custom time blocks.

** Features

- Automatically schedules tasks with the =AUTOSCH= tag
- Considers task priority, deadline, effort, and current state
- Supports custom time blocks for specific tags
- Respects existing scheduled tasks and avoids conflicts
- Customizable scheduling parameters
- Handles project-based task grouping and ordering
- Considers clocked time when calculating remaining effort
- Supports "NOT_BEFORE" property to set the earliest scheduling time for a task

** Usage

To use Org Auto Scheduler, add the =AUTOSCH= tag to any task you want to be automatically scheduled. You can also set a "NOT_BEFORE" property to specify the earliest date and time the task should be scheduled. For example:

#+BEGIN_SRC org
* TODO Task with NOT_BEFORE property :AUTOSCH:
  :PROPERTIES:
  :NOT_BEFORE: <2023-05-15 Mon 09:00>
  :END:

This task will not be scheduled before May 15, 2023, at 9:00 AM.
#+END_SRC

Then run the command:

=M-x org-auto-scheduler-schedule-tasks=

You can also bind this command to a key combination, for example:

=(global-set-key (kbd "C-c a s") 'org-auto-scheduler-schedule-tasks)=

** Customization Options

*** General Settings

- =org-auto-scheduler-start-time=: Start time for scheduling tasks (default: "09:00")
- =org-auto-scheduler-end-time=: End time for scheduling tasks (default: "17:00")
- =org-auto-scheduler-task-gap=: Gap between scheduled tasks in minutes (default: 5)
- =org-auto-scheduler-max-days-to-check=: Maximum number of days to look ahead for scheduling (default: 14)
- =org-auto-scheduler-time-interval=: Interval in minutes for checking time slots (default: 15)
- =org-auto-scheduler-excluded-days=: List of days to exclude from scheduling (0 is Sunday, 6 is Saturday)

*** Scoring Weights

- =org-auto-scheduler-effort-weight=: Weight for remaining effort in score calculation (default: 0.0)
- =org-auto-scheduler-priority-weight=: Weight for priority in score calculation (default: 10.0)
- =org-auto-scheduler-urgency-weight=: Weight for urgency factor in score calculation (default: 20.0)
- =org-auto-scheduler-urgent-days=: Number of days before a deadline is considered urgent (default: 7)

*** Task States

- =org-auto-scheduler-state-weights=: Alist of weights for different TODO states. The keys of this alist are considered valid states for auto-scheduling.
  Default: 
  #+begin_src emacs-lisp
  '(("TODO" . 0)
    ("NEXT" . 1)
    ("IN-PROGRESS" . 2)
    ("WRITE" . 0)
    ("LATER" . -10)
    ("BUY" . 0)
    ("READ" . 0))
  #+end_src

  You can customize this list to match your workflow. For example:

  #+begin_src emacs-lisp
  (setq org-auto-scheduler-state-weights
        '(("TODO" . 0)
          ("NEXT" . 1)
          ("IN-PROGRESS" . 2)
          ("WAITING" . -1)))
  #+end_src

  The auto-scheduler will consider tasks with TODO states that match any key in this alist.

*** Time Blocks

- =org-auto-scheduler-time-blocks=: Alist of time blocks for scheduling tasks with specific tags
  Default:
  #+begin_src emacs-lisp
  '(("FUN" . (("18:00" . "19:00")))
    ("BUYING" . (("14:00" . "15:00")))
    ("CHORES" . (("19:00" . "20:00"))))
  #+end_src

*** Other Settings

- =org-auto-scheduler-inherited-priority-property=: Property name for setting inherited priority for subtasks (default: "INHERITED_PRIORITY")
- =org-auto-scheduler-scheduled-property=: Property name to mark AUTOSCH tasks that have been scheduled in the current session (default: "AUTOSCH_SCHEDULED")
- =org-auto-scheduler-default-task-duration=: Default duration in minutes for tasks without an explicit effort (default: 60)

*** Files to Consider

- =org-auto-scheduler-files=: Specifies which files to consider for auto-scheduling, with optional weights. Can be one of:
  - =(agenda . WEIGHT)=: Use all files in =org-agenda-files= with the specified weight (default)
  - An alist of =(FILE . WEIGHT)= pairs
  - A function that returns an alist of =(FILE . WEIGHT)= pairs

  WEIGHT is a float value used to adjust task scores from the corresponding file.

  Example of custom configuration:
  #+begin_src emacs-lisp
  ;; Use agenda files with default weight
  (setq org-auto-scheduler-files '(agenda . 1.0))

  ;; Use specific files with custom weights
  (setq org-auto-scheduler-files
        '(("~/org/work.org" . 1.2)
          ("~/org/personal.org" . 0.8)))

  ;; Or use a custom function
  (setq org-auto-scheduler-files
        (lambda ()
          (mapcar (lambda (file)
                    (cons file (if (string-match "work" file) 1.2 0.8)))
                  (directory-files "~/org" t "\\.org$"))))
  #+end_src

  Tasks from files with higher weights will be given higher priority in scheduling.

** How It Works

1. The plugin clears existing scheduled times for tasks with the =AUTOSCH= tag.
2. It collects all schedulable tasks (those with =AUTOSCH= tag and valid TODO states).
3. Tasks are sorted based on a calculated score considering priority, deadline, effort, state, and project grouping.
4. Each task is scheduled in the next available time slot, respecting time blocks if applicable.
5. The plugin avoids conflicts with existing scheduled tasks and maintains gaps between tasks.
6. It considers clocked time when calculating remaining effort for tasks.
7. Project-based tasks are grouped and scheduled together.

** Debugging

To debug the auto-scheduler, use the command:

=M-x org-auto-scheduler-debug=

This will run the scheduler with detailed logging and open the log buffer for inspection.

** Recurring Tasks

Org Auto Scheduler supports the automatic scheduling of recurring tasks. To define a recurring task, add the `RECURRING` property to your task with a specified frequency. Supported frequencies include `daily`, `weekly`, `bi-weekly`, and `monthly`.

**Example:**

#+BEGIN_SRC org
* TODO Weekly Team Meeting :AUTOSCH:
  :PROPERTIES:
  :RECURRING: weekly
  :END:

This task will be automatically scheduled every week.
#+END_SRC

**Customization Options:**

- **Frequency Options:**
  - `daily`: The task repeats every day.
  - `weekly`: The task repeats every week.
  - `bi-weekly`: The task repeats every two weeks.
  - `monthly`: The task repeats every month.

- **NOT_BEFORE Property:**
  You can combine the `RECURRING` property with the `NOT_BEFORE` property to specify the earliest date and time the recurring task should be scheduled.

**Example with NOT_BEFORE:**

#+BEGIN_SRC org
* TODO Monthly Report Submission :AUTOSCH:
  :PROPERTIES:
  :RECURRING: monthly
  :NOT_BEFORE: <2024-01-01 Wed 09:00>
  :END:

This task will be automatically scheduled on the first day of each month, not before January 1, 2024, at 9:00 AM.
#+END_SRC

**Notes:**

- Ensure that recurring tasks have appropriate effort estimates for accurate scheduling.
- Recurring tasks will be created based on the specified frequency and will adhere to the `NOT_BEFORE` constraints if set.
- You can manage the recurrence by adjusting the `RECURRING` property or by removing it to stop the task from recurring.

**Troubleshooting:**

If recurring tasks are not being scheduled as expected:

1. Verify that the `RECURRING` property is set with a valid frequency (`daily`, `weekly`, `bi-weekly`, or `monthly`).
2. Ensure that the `AUTOSCH` tag is present on the task.
3. Check the `NOT_BEFORE` property to confirm it does not conflict with your desired scheduling.
4. Use the debugging command `M-x org-auto-scheduler-debug` to inspect detailed logs for any issues related to recurring task scheduling.
